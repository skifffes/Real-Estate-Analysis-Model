#H2 （三）Ghosh供给侧模型
#P 需求侧模型适合分析房地产投资和需求变化，但无法直接回答“钢铁等上游部门供给收缩后风险如何向下游扩散”这一类问题。
#P 因此，本项目增加 Ghosh 供给侧框架。
#P 设中间流量矩阵为 Z，部门总产出构成的对角矩阵为 D = diag(X)，供给分配系数矩阵为：
#CENTER B = D^(-1) Z ，其中 B_ij = Z_ij / X_i
#P 再构造 Ghosh 逆矩阵：
#CENTER G = (I - B)^(-1)
#P 当初始投入或增加值发生变化时：
#CENTER DX = DV (I - B)^(-1)
#P 当前模型按照这一标准口径实现。代码中 B 按卖方部门总产出进行系数化，同时明确指出其行和并不要求等于1。由于 B = D^(-1)AD 与直接消耗矩阵 A 互为相似矩阵，两者谱半径相同（本项目数据下约为 0.7303），矩阵 I-B 数值稳定可逆。
#P 需要注意的是，北京属于跨地区要素和产品流动较强的经济体，地区投入产出表中的中间使用包含调入和进口因素（行平衡关系为：中间使用 + 最终使用 - 进口 = 总产出）。因此，本项目不把 B 简单解释为“北京市本地产出的销售分配比例”，而更谨慎地将其理解为各下游部门对相关产品的中间使用暴露和产业关联强度。系统中的供给侧结果同样被定义为压力测试意义上的情景值。
#P 另外，“钢铁减产10%”与“钢铁增加值下降10%”在理论上并不是完全相同的变量。当前系统将自然语言中的数量型供给收缩映射为同幅度的初始投入变化进行压力测试，并在工具说明中明确标注两者并非严格等价。
#H2 （四）价格与资产价格问题的处理
#P 对于原材料涨价、生产成本上涨以及房价变化，本项目目前不使用 Leontief 或 Ghosh 数量模型给出精确数字。
#P 这是因为价格变化与数量变化的传导机制不同。
#P 例如，钢材涨价首先影响的是下游企业采购成本和利润率，企业能否将成本继续传递给消费者，还受到议价能力、库存、替代材料等因素影响。房价变化则更多通过家庭财富、抵押品价值、融资能力以及房企投资预期间接影响实体需求。
#P 因此，目前系统对上述问题只给出机制分析，并将投入产出价格模型以及价格-需求弹性模型作为后续扩展方向。当前 Agent 的规则和服务端模型守卫均明确禁止将此类问题强行送入数量模型。
#H2 （五）情景风险评分
#P 投入产出模型回答的是“产业关联压力”，但某一行业是否因此形成较高风险，还与其自身资产负债结构和经营状况有关。
#P 因此项目设置了情景风险评分，综合收入压力、债务压力、现金流压力和市场需求压力四个维度，其中收入、债务权重分别为30%，现金流和市场需求分别为20%。
#P 这里必须区分“风险评分”和“企业信用评级”。
#P 目前产业链情景中的收入、现金流和需求指标，并不是全部来自独立的真实财务预测，而是根据投入产出冲击结果进行规则映射：产出影响近似映射为收入变化，现金流压力按照1.5倍进行放大，市场需求按照0.8倍映射，债务项则使用行业基准负债率。
#P 因此，这一评分的用途是：
#CENTERBOLD 比较同一冲击情景下不同行业的相对压力大小。
#P 它不用于给企业授信，也不是对具体公司的违约概率预测。后续随着企业真实经营和现金流数据接入，可以进一步减少代理变量的使用。
